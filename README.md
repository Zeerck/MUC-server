# MUC-server

Простой многопользовательский чат-сервер на Rust с управлением пользователями через SQLite

## Возможности проекта

- Поддержка нескольких одновременных соединений (поток для каждого клиента).
- Регистрация пользователей по IP-адресу и никнейму.
- Валидация никнеймов (3–32 символа, только латиница, цифры и подчёркивание).
- Команды: `/ping` (проверка связи), `/exit` (завершение сессии).
- Логирование с цветным выводом в консоль (уровни: INFO, TRACE, DEBUG, WARNING, ERROR, FATAL).
- Конфигурация через переменные окружения (файл `.env`).
- База данных SQLite с автоматической миграцией и поддержкой WAL-журнала.

## Требования

- Rust (последняя стабильная версия)
- Cargo

## Установка и запуск

1. Клонируем репозиторий:
```bash
git clone https://github.com/Zeerck/MUC-server.git
cd MUC-server
```

2. Копируем пример конфигурации:

```
cp .env.example .env
```
> отредактируйте .env при необходимости

3. Сборка и запуск:
- Debug сборка:
  ```
  cargo run
  ```

- Релизная сборка:
  ```
  cargo build --release
  ```

> По умолчанию сервер слушает `127.0.0.1:8080`. Адрес можно изменить в `.env` через переменную `SERVER_ADDRESS`.

## Конфигурация (`.env`)

| Переменная | Описание | Значение по умолчанию |
|---|---|---|
| `SERVER_ADDRESS` | Адрес и порт | `127.0.0.1:8080` |
| `APP_NAME` | Имя приложения (используется в пути к БД, не рекомендуется изменять) | `MUC-server` |
| `DB_PATH` | Путь к файлу БД (абсолютный или относительный) | `./data/database.sqlite` |
| `NICKNAME_TIMEOUT` | Таймаут на ввод ника при подключении (секунды) | `30` |
| `READ_TIMEOUT` | Таймаут чтения сообщений после авторизации (секунды) | `300` |

> Если переменная не задана, используется значение по умолчанию.

## Команды клиента

- `/ping` – получить от сервера ответ `PONG`.
- `/exit` – корректно завершить соединение.

Все остальные сообщения просто логируются на сервере (пока что не обрабатываются).

## Примечания по работе

- База данных создаётся автоматически при первом запуске в папке, указанной в `DB_PATH` (или в системной директории по умолчанию, если `DB_PATH` не задан).
- Сервер использует один общий `Mutex` на соединение с БД, что гарантирует консистентность данных при многопоточном доступе.
- Для повышения производительности включён режим WAL (`PRAGMA journal_mode=WAL`).
